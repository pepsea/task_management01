# タスク＆アイディアハブ 設計仕様

- 作成日: 2026-09-28
- ステータス: レビュー待ち

## 1. 目的

個人のタスク管理・個人ブレスト・アイディア保管を、1つの画面で行えるローカルWebアプリ。

- 利用者: 本人のみ（認証なし・共有なし）
- 実行環境: このMac上のローカルサーバー `http://localhost:5003`
- 成功基準:
  - 1画面でガントチャート・アイディア保管庫・ブレストメモを同時に見られる
  - 思いついたことを数秒で書き留められる
  - アイディアを2クリック程度でタスクに変換できる
  - データはサーバーを再起動しても残る

## 2. 技術構成

| 項目 | 採用 |
|---|---|
| バックエンド | Python 3 + FastAPI + Uvicorn |
| DB | SQLite（標準ライブラリ `sqlite3`、ファイル `data/app.db`） |
| フロントエンド | 素の HTML / CSS / JavaScript（ビルド不要）、FastAPI の StaticFiles で配信 |
| バリデーション | Pydantic モデル |
| テスト | pytest + FastAPI TestClient（一時DBを使用） |

起動方法: `uvicorn app.main:app --port 5003`（`run.sh` にまとめる）

依存パッケージ: `fastapi`, `uvicorn`, `pytest`, `httpx`（TestClient用）。`requirements.txt` で管理し、`.venv` に入れる。

## 4. データモデル

### tasks
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| area | TEXT NOT NULL | 領域（例: 仕事, プライベート） |
| related | TEXT | 関連項目（プロジェクト名等、空可） |
| title | TEXT NOT NULL | タスク名 |
| start_at | TEXT NOT NULL | 開始日時 ISO8601（`YYYY-MM-DDTHH:MM`） |
| due_at | TEXT NOT NULL | 期限 ISO8601。`start_at` 以上であること |
| priority | TEXT NOT NULL | `high` / `mid` / `low` |
| done | INTEGER NOT NULL DEFAULT 0 | 完了フラグ |
| idea_id | INTEGER NULL | 元アイディア（ideas.id、削除時 NULL） |
| created_at / updated_at | TEXT | |

### ideas
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT NOT NULL | |
| body | TEXT NOT NULL DEFAULT '' | 本文（プレーンテキスト） |
| created_at / updated_at | TEXT | |

「タスク化済み」は `tasks.idea_id` の存在で判定する（列の二重管理をしない）。

### brainstorm
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| text | TEXT NOT NULL | 1行メモ |
| created_at | TEXT | |

### decisions（ディシジョンポイント）
全体共通の節目（重要な会議・判断日など）。タスクや領域には属さない。

| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT NOT NULL | 名前（例: 経営会議） |
| date | TEXT NOT NULL | 日付 `YYYY-MM-DD` |
| time | TEXT NULL | 時刻 `HH:MM`（任意） |
| created_at / updated_at | TEXT | |

## 5. API

すべて JSON。エラーは FastAPI 標準（422: 入力不正、404: 存在しない）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/tasks?area= | 一覧（開始日時順）。area で絞り込み可 |
| POST | /api/tasks | 作成 |
| PATCH | /api/tasks/{id} | 部分更新（完了チェック含む） |
| DELETE | /api/tasks/{id} | 削除 |
| GET | /api/areas | 登録済み領域の一覧（絞り込み・入力候補用） |
| GET | /api/ideas?q= | 一覧（更新日の新しい順）。q でタイトル・本文を部分一致検索。各要素に `task_count` を含む |
| POST | /api/ideas | 作成 |
| GET | /api/ideas/{id} | 詳細 |
| PATCH | /api/ideas/{id} | 更新 |
| DELETE | /api/ideas/{id} | 削除（紐づくタスクの idea_id は NULL に） |
| GET | /api/brainstorm | 一覧（新しい順） |
| POST | /api/brainstorm | 追加 |
| DELETE | /api/brainstorm/{id} | 削除 |
| POST | /api/brainstorm/{id}/promote | アイディアに昇格：text をタイトルにした idea を作成し、メモを削除。作成した idea を返す |
| GET | /api/decisions | ディシジョンポイント一覧（日付・時刻順） |
| POST | /api/decisions | 作成 |
| PATCH | /api/decisions/{id} | 部分更新（time を null にすると時刻なし） |
| DELETE | /api/decisions/{id} | 削除 |

タスク化はフロント側で「元アイディアの値を初期値にしたタスク作成フォーム」を開き、`POST /api/tasks` に `idea_id` を付けて送る（専用APIは作らない）。

## 6. 画面

```
┌──────────────────────────────────────────────┬──────────────────────┐
│ [領域▼] [週|月] [◀ 今日 ▶] [+ディシジョン][+タスク]│ アイディア保管庫 [+] │
├──────────────────────────────────────────────┤ [検索____________]   │
│ 領域 │関連 │タスク名 │開始 │期限 │優先│ 日付軸 │ ・アイディアA  ✓     │
│ ディシジョン                      │  ◆経営会議 │ ・アイディアB        │
│ 仕事 │PJ-A │資料作成 │9/28 │10/2 │ 高 │ ███┆   │ ──────────────────── │
│ 私用 │     │引越準備 │10/1 │10/9 │ 中 │   █┆██ │ タイトル [タスク化]  │
│                                         │ ¦今日  │                      │
│                                              │ 本文（自動保存）     │
│                                              ├──────────────────────┤
│                                              │ ブレスト             │
│                                              │ [思いつきを入力 ⏎]   │
│                                              │ ・メモ1   [→保管庫][×]│
└──────────────────────────────────────────────┴──────────────────────┘
          左 2/3                                        右 1/3
```

### 左 2/3：ガントチャート
- 左側は固定の表：領域｜関連項目｜タスク名｜開始｜期限｜優先度｜完了チェック
- 右側は日付軸：週表示（1日＝広め）／月表示（1日＝狭め）を切り替える。◀▶で期間を移動し、「今日」で今日に戻る
- バーは開始日から期限日までを日単位で描画。時刻は表とツールチップで表示
- 優先度で色分け：高＝赤、中＝橙、低＝灰。完了は薄く＋取り消し線、期限切れの未完了は赤枠
- 今日の位置に縦線
- 並び順：領域 → 開始日時
- 領域で絞り込み（ドロップダウン、「すべて」がデフォルト）
- 行クリックでモーダルの編集フォーム（削除ボタンあり）。「+タスク」で同じフォームを新規作成として開く
- 領域・関連項目の入力欄は、既存の値を候補として表示する（`<datalist>`）

#### ディシジョンポイント
- 日付見出しのすぐ下に「ディシジョン」行を1行設け、該当日の位置に ◆＋名前を表示する（名前が長い場合は省略し、ツールチップで全文と日時を表示）
- 同じ日付の位置に、全タスク行を貫く紫の縦破線を引く（今日の青線と区別する）
- 領域の絞り込みに関係なく、常にすべて表示する
- ツールバーの「＋ ディシジョン」で作成ダイアログ（名前・日付・時刻（任意））を開く
- ◆をクリックすると同じダイアログが編集モードで開き、修正・削除（確認あり）ができる

### 右 1/3 上：アイディア保管庫
- 検索欄＋タイトル一覧（タスク化済みには ✓ 印）
- 選ぶと下に編集欄（タイトル・本文 textarea）。入力停止から約800ms後に自動保存し、「保存済み」と表示
- 「タスク化」ボタン：タスク名＝アイディアのタイトル、開始＝今日、期限＝今日から7日後、優先度＝中を初期値にしたタスクフォームを開く。保存すると `idea_id` で紐づく
- 削除ボタン（確認ダイアログあり）

### 右 1/3 下：ブレスト
- 1行入力欄。Enter で追加し、入力欄にフォーカスを残す（連続で書ける）
- 一覧の各行に［→保管庫］（昇格）と［×］（削除）のボタン
- 昇格すると保管庫の一覧に追加され、そのアイディアが選択された状態になる

## 7. エラー処理
- サーバー：Pydantic で入力を検証（必須項目、priority の値、`due_at >= start_at`）。存在しないIDは 404
- フロント：API が失敗したら画面右下にトーストでメッセージを表示。フォームの入力エラーはフォーム内に表示
- 自動保存が失敗したら「保存失敗」と表示し、次の入力で再試行する

## 8. テスト
- API：pytest + TestClient で各エンドポイントの正常系と主な異常系を確認（422、404、期限 < 開始、昇格でメモが消えアイディアができる、アイディア削除時に idea_id が NULL になる、area での絞り込み、q 検索、ディシジョンの日付・時刻の形式チェックと時刻の解除）
- DB は各テストで一時ファイルを使う（`db.py` の DB パスを環境変数 `APP_DB_PATH` で差し替え可能にする）
- フロント：自動テストは作らず、実装後にブラウザで主要操作（追加・編集・完了・タスク化・昇格・再読み込み後にデータが残ること）を手動で確認する

## 9. 対象外（今回は作らない）
- ガントバーのドラッグ操作、タスク間の依存関係、サブタスク
- 認証、複数ユーザー、同期、スマホ向けレイアウト
- Markdown レンダリング、添付ファイル
- JSON の書き出し・読み込み（DB ファイルのコピーでバックアップする）

## 10. 追加要件（2026-09-28 実装時に追加）

### 10.1 ガントの表示単位（日・週・月）
- ツールバーで「日｜週｜月」を切り替える。1 列の単位が変わる
  - 日: 1 列 = 1 日、今週の月曜から 14 日。◀▶ は 7 日ずつ移動
  - 週: 1 列 = 1 週（月曜始まり）、13 週。◀▶ は 4 週ずつ移動
  - 月: 1 列 = 1 か月、表示中の月から 12 か月。◀▶ は 1 か月ずつ移動
- 列幅は左ペインの空き幅に合わせて広げ、狭いときは下限（日 28px / 週 44px / 月 56px）で横スクロール
- バー・今日線・ディシジョンは 1 日あたりの幅で位置を計算する（月は日数が違うので列幅も違う）
- 近い日付のディシジョン名が重なるときは 2 段に振り分ける

### 10.2 タスクのメモ
- `tasks.memo`（TEXT、既定 `''`、最大 10000 文字）。既存 DB には起動時に列を追加する
- タスクダイアログにメモ欄。メモがあるタスクはタスク名の前に 📝 を表示し、ツールチップで全文を表示
- アイディアのメモは既存の本文（body）で扱う

### 10.3 アイディアのタグ
- `tags(id, name UNIQUE, color)` と `idea_tags(idea_id, tag_id, position)`
- アイディアの編集欄でタグ名を入力して Enter で付ける（未登録の名前は自動作成、使用数の少ない色を自動割り当て）。× で外す
- 一覧のタイトル横にタグを色付きで表示。タグで絞り込み（`GET /api/ideas?tag=`）
- API: `GET /api/tags`、`PATCH /api/tags/{id}`（name / color `#rrggbb`、重複名は 409）、`DELETE /api/tags/{id}`
- アイディアの作成・更新は `tags: string[]` を受け付け、指定時は丸ごと置き換える

### 10.4 領域・関連項目の登録制（登録画面）
- `areas(id, name UNIQUE)` と `related_items(id, name UNIQUE)`。領域と関連項目は互いに独立したマスタ（どの領域のタスクでも、どの関連項目も使える）
- 登録画面 `/settings.html`（ツールバーの「⚙ 登録」）に「領域」「関連項目」「アイディアのタグ」の3カード。追加・名前変更・削除、タグは色も変更できる。説明文は置かない
- タスクの領域・関連項目はプルダウンで選ぶ。未登録の値は 422
- 名前を変更すると既存タスクにも反映する。タスクで使われているものは削除できない（409）
- 既存タスクの値は起動時にマスタへ取り込む。関連項目が領域の下にあった旧スキーマは起動時に独立した表へ作り直す
- API: `GET/POST /api/areas`、`PATCH/DELETE /api/areas/{id}`、`GET/POST /api/related`、`PATCH/DELETE /api/related/{id}`

### 10.5 アイディアのアーカイブ
- `ideas.archived_at`（NULL = 保管庫）。`PATCH /api/ideas/{id}` の `archived: true/false` でアーカイブ・復元（updated_at は変えない）
- `GET /api/ideas` は既定で保管庫のみ。`archived=true` でアーカイブ済みをアーカイブの新しい順に返す（検索・タグ絞り込みも可）
- 保管庫の編集欄に「アーカイブ」ボタン、見出しに「🗄 アーカイブ」リンク
- アーカイブ画面 `/archive.html`: タイトル・タグ・本文・日付（思いつき・更新・アーカイブ）をカードでそのまま表示。「保管庫に戻す」「削除」

### 10.6 今日のタスク
- `tasks.today_on`（今日のタスクに選んだ日付 `YYYY-MM-DD`）。その日だけ有効で、翌日は自動的に外れる
- ガントの各行の先頭に ☀ ボタン。今日のタスクは行を黄色で強調し、タスク名を太字、バーに黄色の縁取り
- ツールバーの「☀ 今日 n」で今日のタスクだけに絞り込む

### 10.7 ディシジョンの縦並び
- ディシジョンは 1 件ずつ、名前が重ならない一番上の段に置く。同じ日の複数件や近い日付は下の段に縦に並び、ディシジョン行の高さは段数に合わせて伸びる

### 10.8 思いつき日時
- ブレストメモの作成日時を各メモの横に表示する
- 保管庫へ移すと、アイディアの作成日時（思いつき日時）はメモの日時を引き継ぐ
- アイディアの編集欄とアーカイブ画面に「思いつき」「更新」日時を表示する

### 10.9 アイディア保管庫の別ページ化
- アイディア保管庫は `/ideas.html`（左: 登録・検索・タグ絞り込み・一覧、右: 編集欄）。メイン画面の右ペインはブレストのみ（左右 3:1）
- メイン画面のツールバーとブレスト見出しから保管庫へリンク。保管庫の「タスク化」は `/?idea=ID` でメイン画面を開き、タスク作成ダイアログを表示する
- ブレストの「→保管庫」は保管庫に移したことをトーストで知らせる
- 一覧の各行は 1 行で、☆/★・タイトル・タグ・タスク化済み ✓ を表示（本文は出さない）。☆/★ のクリックで「優先」（`ideas.prioritized`）を切り替え、優先は黄色で強調して先頭に並べる（切り替えで updated_at は変えない）

### 10.10 タスクの Web リンク
- `tasks.links`（`[{url, label}]` の JSON、最大 20 件）。URL は前後の空白を除き、http/https でホストを含むもののみ（javascript: などは 422）
- タスクダイアログで URL・表示名の行を追加・削除し、「開く」で新しいタブに開ける
- ガントのタスク名の前に 🔗（複数なら 🔗n）。クリックで最初のリンクを新しいタブで開き、ツールチップに全リンクを表示

### 10.11 領域の色
- `areas.color`。登録時にタグと同じパレットから使用数の少ない色を自動割り当て（既存の領域は起動時に割り当て）。登録画面で変更できる
- ガントの領域欄をその色のラベルで表示する（バーの色は優先度のまま）

### 10.12 ガントの並び順
- タスクは締切（期限）の早い順、同じ締切は開始の早い順
