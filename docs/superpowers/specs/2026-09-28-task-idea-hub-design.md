# タスク＆アイディアハブ 設計仕様

- 作成日: 2026-09-28
- ステータス: レビュー待ち

## 1. 目的

個人のタスク管理・個人ブレスト・アイディア保管を、1つの画面で行えるローカルWebアプリ。

- 利用者: 本人のみ（認証なし・共有なし）
- 実行環境: このMac上のローカルサーバー `http://localhost:5003`
- 成功基準:
  - 1画面でガントチャート・アイディア保管庫・ブレストメモを同時に見られる
  - 思いついたことを数秒で書き留められる
  - アイディアを2クリック程度でタスクに変換できる
  - データはサーバーを再起動しても残る

## 2. 技術構成

| 項目 | 採用 |
|---|---|
| バックエンド | Python 3 + FastAPI + Uvicorn |
| DB | SQLite（標準ライブラリ `sqlite3`、ファイル `data/app.db`） |
| フロントエンド | 素の HTML / CSS / JavaScript（ビルド不要）、FastAPI の StaticFiles で配信 |
| バリデーション | Pydantic モデル |
| テスト | pytest + FastAPI TestClient（一時DBを使用） |

起動方法: `uvicorn app.main:app --port 5003`（`run.sh` にまとめる）

依存パッケージ: `fastapi`, `uvicorn`, `pytest`, `httpx`（TestClient用）。`requirements.txt` で管理し、`.venv` に入れる。

## 4. データモデル

### tasks
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| area | TEXT NOT NULL | 領域（例: 仕事, プライベート） |
| related | TEXT | 関連項目（プロジェクト名等、空可） |
| title | TEXT NOT NULL | タスク名 |
| start_at | TEXT NOT NULL | 開始日時 ISO8601（`YYYY-MM-DDTHH:MM`） |
| due_at | TEXT NOT NULL | 期限 ISO8601。`start_at` 以上であること |
| priority | TEXT NOT NULL | `high` / `mid` / `low` |
| done | INTEGER NOT NULL DEFAULT 0 | 完了フラグ |
| idea_id | INTEGER NULL | 元アイディア（ideas.id、削除時 NULL） |
| created_at / updated_at | TEXT | |

### ideas
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT NOT NULL | |
| body | TEXT NOT NULL DEFAULT '' | 本文（プレーンテキスト） |
| created_at / updated_at | TEXT | |

「タスク化済み」は `tasks.idea_id` の存在で判定する（列の二重管理をしない）。

### brainstorm
| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| text | TEXT NOT NULL | 1行メモ |
| created_at | TEXT | |

### decisions（ディシジョンポイント）
全体共通の節目（重要な会議・判断日など）。タスクや領域には属さない。

| 列 | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT NOT NULL | 名前（例: 経営会議） |
| date | TEXT NOT NULL | 日付 `YYYY-MM-DD` |
| time | TEXT NULL | 時刻 `HH:MM`（任意） |
| created_at / updated_at | TEXT | |

## 5. API

すべて JSON。エラーは FastAPI 標準（422: 入力不正、404: 存在しない）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | /api/tasks?area= | 一覧（開始日時順）。area で絞り込み可 |
| POST | /api/tasks | 作成 |
| PATCH | /api/tasks/{id} | 部分更新（完了チェック含む） |
| DELETE | /api/tasks/{id} | 削除 |
| GET | /api/areas | 登録済み領域の一覧（絞り込み・入力候補用） |
| GET | /api/ideas?q= | 一覧（更新日の新しい順）。q でタイトル・本文を部分一致検索。各要素に `task_count` を含む |
| POST | /api/ideas | 作成 |
| GET | /api/ideas/{id} | 詳細 |
| PATCH | /api/ideas/{id} | 更新 |
| DELETE | /api/ideas/{id} | 削除（紐づくタスクの idea_id は NULL に） |
| GET | /api/brainstorm | 一覧（新しい順） |
| POST | /api/brainstorm | 追加 |
| DELETE | /api/brainstorm/{id} | 削除 |
| POST | /api/brainstorm/{id}/promote | アイディアに昇格：text をタイトルにした idea を作成し、メモを削除。作成した idea を返す |
| GET | /api/decisions | ディシジョンポイント一覧（日付・時刻順） |
| POST | /api/decisions | 作成 |
| PATCH | /api/decisions/{id} | 部分更新（time を null にすると時刻なし） |
| DELETE | /api/decisions/{id} | 削除 |

タスク化はフロント側で「元アイディアの値を初期値にしたタスク作成フォーム」を開き、`POST /api/tasks` に `idea_id` を付けて送る（専用APIは作らない）。

## 6. 画面

```
┌──────────────────────────────────────────────┬──────────────────────┐
│ [領域▼] [週|月] [◀ 今日 ▶] [+ディシジョン][+タスク]│ アイディア保管庫 [+] │
├──────────────────────────────────────────────┤ [検索____________]   │
│ 領域 │関連 │タスク名 │開始 │期限 │優先│ 日付軸 │ ・アイディアA  ✓     │
│ ディシジョン                      │  ◆経営会議 │ ・アイディアB        │
│ 仕事 │PJ-A │資料作成 │9/28 │10/2 │ 高 │ ███┆   │ ──────────────────── │
│ 私用 │     │引越準備 │10/1 │10/9 │ 中 │   █┆██ │ タイトル [タスク化]  │
│                                         │ ¦今日  │                      │
│                                              │ 本文（自動保存）     │
│                                              ├──────────────────────┤
│                                              │ ブレスト             │
│                                              │ [思いつきを入力 ⏎]   │
│                                              │ ・メモ1   [→保管庫][×]│
└──────────────────────────────────────────────┴──────────────────────┘
          左 2/3                                        右 1/3
```

### 左 2/3：ガントチャート
- 左側は固定の表：領域｜関連項目｜タスク名｜開始｜期限｜優先度｜完了チェック
- 右側は日付軸：週表示（1日＝広め）／月表示（1日＝狭め）を切り替える。◀▶で期間を移動し、「今日」で今日に戻る
- バーは開始日から期限日までを日単位で描画。時刻は表とツールチップで表示
- 優先度で色分け：高＝赤、中＝橙、低＝灰。完了は薄く＋取り消し線、期限切れの未完了は赤枠
- 今日の位置に縦線
- 並び順：領域 → 開始日時
- 領域で絞り込み（ドロップダウン、「すべて」がデフォルト）
- 行クリックでモーダルの編集フォーム（削除ボタンあり）。「+タスク」で同じフォームを新規作成として開く
- 領域・関連項目の入力欄は、既存の値を候補として表示する（`<datalist>`）

#### ディシジョンポイント
- 日付見出しのすぐ下に「ディシジョン」行を1行設け、該当日の位置に ◆＋名前を表示する（名前が長い場合は省略し、ツールチップで全文と日時を表示）
- 同じ日付の位置に、全タスク行を貫く紫の縦破線を引く（今日の青線と区別する）
- 領域の絞り込みに関係なく、常にすべて表示する
- ツールバーの「＋ ディシジョン」で作成ダイアログ（名前・日付・時刻（任意））を開く
- ◆をクリックすると同じダイアログが編集モードで開き、修正・削除（確認あり）ができる

### 右 1/3 上：アイディア保管庫
- 検索欄＋タイトル一覧（タスク化済みには ✓ 印）
- 選ぶと下に編集欄（タイトル・本文 textarea）。入力停止から約800ms後に自動保存し、「保存済み」と表示
- 「タスク化」ボタン：タスク名＝アイディアのタイトル、開始＝今日、期限＝今日から7日後、優先度＝中を初期値にしたタスクフォームを開く。保存すると `idea_id` で紐づく
- 削除ボタン（確認ダイアログあり）

### 右 1/3 下：ブレスト
- 1行入力欄。Enter で追加し、入力欄にフォーカスを残す（連続で書ける）
- 一覧の各行に［→保管庫］（昇格）と［×］（削除）のボタン
- 昇格すると保管庫の一覧に追加され、そのアイディアが選択された状態になる

## 7. エラー処理
- サーバー：Pydantic で入力を検証（必須項目、priority の値、`due_at >= start_at`）。存在しないIDは 404
- フロント：API が失敗したら画面右下にトーストでメッセージを表示。フォームの入力エラーはフォーム内に表示
- 自動保存が失敗したら「保存失敗」と表示し、次の入力で再試行する

## 8. テスト
- API：pytest + TestClient で各エンドポイントの正常系と主な異常系を確認（422、404、期限 < 開始、昇格でメモが消えアイディアができる、アイディア削除時に idea_id が NULL になる、area での絞り込み、q 検索、ディシジョンの日付・時刻の形式チェックと時刻の解除）
- DB は各テストで一時ファイルを使う（`db.py` の DB パスを環境変数 `APP_DB_PATH` で差し替え可能にする）
- フロント：自動テストは作らず、実装後にブラウザで主要操作（追加・編集・完了・タスク化・昇格・再読み込み後にデータが残ること）を手動で確認する

- 認証、複数ユーザー、同期、スマホ向けレイアウト
- Markdown レンダリング、添付ファイル
- JSON の書き出し・読み込み（DB ファイルのコピーでバックアップする）

## 10. 追加要件（2026-09-28 実装時に追加）

### 10.1 ガントの表示単位（日・週・月）
- ツールバーで「日｜週｜月」を切り替える。1 列の単位が変わる
  - 日: 1 列 = 1 日、今週の月曜から 14 日。◀▶ は 7 日ずつ移動
  - 週: 1 列 = 1 週（月曜始まり）、13 週。◀▶ は 4 週ずつ移動
  - 月: 1 列 = 1 か月、表示中の月から 12 か月。◀▶ は 1 か月ずつ移動
- 列幅は左ペインの空き幅に合わせて広げ、狭いときは下限（日 28px / 週 44px / 月 56px）で横スクロール
- バー・今日線・ディシジョンは 1 日あたりの幅で位置を計算する（月は日数が違うので列幅も違う）
- 近い日付のディシジョン名が重なるときは 2 段に振り分ける

### 10.2 タスクのメモ
- `tasks.memo`（TEXT、既定 `''`、最大 10000 文字）。既存 DB には起動時に列を追加する
- タスクダイアログにメモ欄。メモはタスク名のツールチップで全文を表示する（印は付けない）
- アイディアのメモは既存の本文（body）で扱う

### 10.3 アイディアのタグ
- `tags(id, name UNIQUE, color)` と `idea_tags(idea_id, tag_id, position)`
- アイディアの編集欄でタグ名を入力して Enter で付ける（未登録の名前は自動作成、使用数の少ない色を自動割り当て）。× で外す
- 一覧のタイトル横にタグを色付きで表示。タグで絞り込み（`GET /api/ideas?tag=`）
- API: `GET /api/tags`、`PATCH /api/tags/{id}`（name / color `#rrggbb`、重複名は 409）、`DELETE /api/tags/{id}`
- アイディアの作成・更新は `tags: string[]` を受け付け、指定時は丸ごと置き換える

### 10.4 領域・関連項目の登録制（登録画面）
- `areas(id, name UNIQUE)` と `related_items(id, name UNIQUE)`。領域と関連項目は互いに独立したマスタ（どの領域のタスクでも、どの関連項目も使える）
- 登録画面 `/settings.html`（ツールバーの「⚙ 登録」）に「領域」「関連項目」「アイディアのタグ」の3カード。追加・名前変更・削除、タグは色も変更できる。説明文は置かない
- タスクの領域・関連項目はプルダウンで選ぶ。未登録の値は 422
- 名前を変更すると既存タスクにも反映する。タスクで使われているものは削除できない（409）
- 既存タスクの値は起動時にマスタへ取り込む。関連項目が領域の下にあった旧スキーマは起動時に独立した表へ作り直す
- API: `GET/POST /api/areas`、`PATCH/DELETE /api/areas/{id}`、`GET/POST /api/related`、`PATCH/DELETE /api/related/{id}`

### 10.5 アイディアのアーカイブ
- `ideas.archived_at`（NULL = 保管庫）。`PATCH /api/ideas/{id}` の `archived: true/false` でアーカイブ・復元（updated_at は変えない）
- `GET /api/ideas` は既定で保管庫のみ。`archived=true` でアーカイブ済みをアーカイブの新しい順に返す（検索・タグ絞り込みも可）
- 保管庫の編集欄に「アーカイブ」ボタン、見出しに「🗄 アーカイブ」リンク
- アーカイブ画面 `/archive.html`: タイトル・タグ・本文・日付（思いつき・更新・アーカイブ）をカードでそのまま表示。「保管庫に戻す」「削除」

### 10.6 今日のタスク
- `tasks.today_on`（今日のタスクに選んだ日付 `YYYY-MM-DD`）。その日だけ有効で、翌日は自動的に外れる
- ガントの各行の先頭に ☀ ボタン。今日のタスクは行を黄色で強調し、タスク名を太字、バーに黄色の縁取り
- ツールバーの「☀ 今日 n」で今日のタスクだけに絞り込む

### 10.7 ディシジョンの縦並び
- ディシジョンは 1 件ずつ、名前が重ならない一番上の段に置く。同じ日の複数件や近い日付は下の段に縦に並び、ディシジョン行の高さは段数に合わせて伸びる

### 10.8 思いつき日時
- ブレストメモの作成日時を各メモの横に表示する
- 保管庫へ移すと、アイディアの作成日時（思いつき日時）はメモの日時を引き継ぐ
- アイディアの編集欄とアーカイブ画面に「思いつき」「更新」日時を表示する

### 10.9 アイディア保管庫の別ページ化
- アイディア保管庫は `/ideas.html`（左: 登録・検索・タグ絞り込み・一覧、右: 編集欄）。メイン画面の右ペインはブレストのみ（左右 3:1）
- メイン画面のツールバーとブレスト見出しから保管庫へリンク。保管庫の「タスク化」は `/?idea=ID` でメイン画面を開き、タスク作成ダイアログを表示する
- ブレストの「→保管庫」は保管庫に移したことをトーストで知らせる
- 一覧の各行は 1 行で、☆/★・タイトル・タグ・タスク化済み ✓ を表示（本文は出さない）。☆/★ のクリックで「優先」（`ideas.prioritized`）を切り替え、優先は黄色で強調して先頭に並べる（切り替えで updated_at は変えない）

### 10.10 タスクの Web リンク
- `tasks.links`（`[{url, label}]` の JSON、最大 20 件）。URL は前後の空白を除き、http/https でホストを含むもののみ（javascript: などは 422）
- タスクダイアログで URL・表示名の行を追加・削除し、「開く」で新しいタブに開ける
- ガントのタスク名の横にリンクを小さく並べる（表示名、なければドメイン。10.30 参照）。クリックでそのリンクを新しいタブで開く

### 10.11 領域の色
- `areas.color`。登録時にタグと同じパレットから使用数の少ない色を自動割り当て（既存の領域は起動時に割り当て）。登録画面で変更できる
- ガントの領域欄をその色のラベルで表示する。バーの色も領域の色にする（10.31。優先度は「優先」列の文字色で表す）

### 10.12 ガントの並び順
- 今日のタスク → その他の未完了 → 完了の順に並べる（完了は今日のタスクでも一番下）。それぞれの中は期限の日付の早い順、同じ日付は優先度の高い順（高 → 中 → 低）、同じ優先度は期限の時刻・開始の早い順

### 10.13 期限が近いタスク
- 未完了で、期限が今日・明日・明後日（残り 2 日以内、日付単位）のタスクは期限を赤字で表示する（期限切れは従来どおり赤字＋バーの赤枠）

### 10.14 表の列幅と折りたたみ
- 初期幅: ☀ 32 / 領域 110 / 関連項目 100 / タスク名 240 / 開始 60 / 期限 60 / 優先 42 / 完了 42（px）
- 開始・期限は月日（M/D）のみ表示し、時刻はツールチップで表示する
- 見出しの右端をドラッグして列幅を変更（最小 32px）、ダブルクリックで初期幅に戻す
- タスク名の見出しのボタン（◂ / ▸ 詳細）で「開始・期限・優先・完了」をまとめて折りたたむ
- 折りたたみ中は、期限切れ・残り 2 日以内の未完了タスクのタスク名を赤字にする
- 列幅と折りたたみの状態はブラウザ（localStorage `gantt.table`）に保存する。表の幅が変わると日付欄の列数も変わる

### 10.15 アイディアの並べ替え
- `ideas.position`（手動の並び順）。保管庫は ★（優先）を先頭に、その中は position 順。新規登録・ブレストからの移動は一番上。本文の更新や ★ の切り替えでは順番は変わらない
- 導入前のアイディアは、更新の新しい順を初期の並び順にする
- 一覧の行（左端に ⋮⋮）をドラッグして並べ替える。★ のグループをまたぐ移動はできない
- `POST /api/ideas/reorder {ids}`: 渡された ID が使っている並び順の値を、渡された順に割り当て直す（絞り込みで見えていないアイディアの位置は変わらない）。重複 422、存在しない ID 404

### 10.16 上部タブ
- 全ページの上部に共通タブ「TODO / NOTES / アイディア / 登録 / アーカイブ」（static/nav.js）。各ページにあった「← ガントに戻る」等のリンクはタブに置き換えた
- アーカイブは 1 ページで「アイディア / メモ」を切り替える（`/archive.html?kind=notes`）

### 10.17 NOTES（Markdown メモ帳）
- `/notes.html`。左: 新規・検索・タグ絞り込み・一覧（★ ピン留めを先頭、日付の新しい順。10.19 参照）、右: エディタ（自動保存、ページを離れるときも保存）
- タイトルは 10.20 参照（当初は本文の最初の行から自動生成していた）
- エディタは Typora 風のブロック単位: 空行で区切ったブロックを整形表示し、クリックしたブロックだけ原文を編集。↑↓ で前後のブロック、Enter 2 回で次のブロック、リストの行で Enter は記号を続ける、Tab / Shift+Tab で字下げ、チェックボックスはクリックで切り替え
- Markdown はサーバー側で変換（`POST /api/markdown {blocks}`、Python-Markdown + nh3 で無害化）。表・コード・取り消し線・チェックリスト・引用・リンク・区切り線に対応。2 スペースの入れ子リスト可。表・リスト・コードブロックの前に空行がなくても認識する（空行を補ってから変換）
- API: `GET/POST /api/notes`（q・tag・archived）、`GET/PATCH/DELETE /api/notes/{id}`（body・tags・pinned・archived）、`POST /api/notes/reorder`
- タグはアイディアと共用（登録画面の「タグ（アイディア・メモ共通）」で管理）

### 10.18 メモの日付
- `notes.note_date`（`YYYY-MM-DD`、必須）。作成時は今日（`note_date` を渡せばその日）。既存のメモは作成日を入れる
- 編集欄の 📅 で変更（変更で updated_at を更新）。一覧とアーカイブのカードに日付を表示（今年なら年を省略）

### 10.19 NOTES の並び・見た目の調整
- 一覧は ★（ピン留め）を先頭に、メモの日付の新しい順（同じ日付は後から作ったものが上）。ドラッグでの並べ替えと `POST /api/notes/reorder` は廃止
- エディタのブロックにマウスを乗せても背景を変えない
- `…` で囲んだ行内コードは半透明のエンジ色の背景（rgba(183,40,46,.12)）とエンジ系の文字色（#9e1f28）。コードブロックは従来どおり

### 10.20 NOTES のタイトル欄と並び順の切り替え
- タイトルは本文とは別の欄で入力する（`notes.title`、最大 100 文字、空可。空は「無題」と表示）。本文の 1 行目からの自動生成は廃止。既存のメモのタイトルは引き継ぐ
- 一覧の上に「日付順｜手動」の切り替え（ブラウザに保存）。⋮⋮ をドラッグして並べ替え（日付順のときにドラッグすると手動に切り替わる。10.37）（`GET /api/notes?sort=manual`、`POST /api/notes/reorder`）。どちらも ★ は先頭
- 新しいメモはタイトル欄から書き始め、Enter で本文へ

### 10.21 アーカイブの 1 行表示
- アーカイブはカードではなく 1 行のリスト（タイトル・タグ・✓ または 📅 日付・アーカイブ日時・戻す・削除）。行をクリックすると下に本文と日付を開く

### 10.22 メモのエクスポート
- NOTES の編集欄の「⬇ エクスポート」とアーカイブのメモ行の「⬇」で、1 件ずつ Markdown ファイルを保存する（ブラウザ内で生成、サーバー API なし）
- 中身は `# タイトル` の下に本文。ファイル名は `日付_タイトル.md`（ファイル名に使えない文字は `_`）

### 10.23 リンクリスト（TODO 画面の右上）
- 右ペインのブレストの上に「リンク」一覧。＋でタイトル（任意）とリンク先を登録、✎ で編集、× で削除、⋮⋮ ドラッグで並べ替え（新規は一番上）
- `quick_links(id, title, target, position, created_at)`。種類はリンク先から判定: web（http/https）・smb（smb://）・path（`C:\` `C:/` `\\サーバー\` `//サーバー/` `file://`）。それ以外（javascript: など）は 422
- web は新しいタブで開く。smb はそのまま開く（Mac では Finder）。path はブラウザの制限で開けないため、クリックでパスをクリップボードにコピーし、エクスプローラーや Finder に貼り付けるよう案内する
- API: `GET/POST /api/links`、`PATCH/DELETE /api/links/{id}`、`POST /api/links/reorder`

### 10.24 Docker
- `Dockerfile`（python:3.14-slim、TZ=Asia/Tokyo、root 以外の appuser で uvicorn を 5003 番で起動、/api/health でヘルスチェック）
- `docker-compose.yml`: `127.0.0.1:5003:5003`（このパソコンからのみ）、`./data` を `/app/data` にマウント（既存のデータをそのまま使う）、`restart: unless-stopped`
- 依存は実行用 `requirements.txt` と開発・テスト用 `requirements-dev.txt` に分けた
- 起動は `docker-entrypoint.sh` 経由: root で起動し、`/app/data` を appuser が書き込めなければ所有者を appuser に変更してから、`setpriv` で appuser に切り替えて uvicorn を実行する（Linux で ./data が root の持ち物になり「unable to open database file」で起動に失敗した問題への対応）

### 10.25 ログイン（1 アカウント）
- `users(id, username, password_hash, created_at)`・`sessions(token_hash, user_id, created_at, renewed_at, expires_at)`
- アカウントが無ければ全画面が `/setup.html`（初回設定: ユーザー名・パスワード 8 文字以上）へ。作成後は 1 アカウントのみ（2 回目は 409）
- 未ログインの API は 401、画面は `/login.html` へ 303。公開パスはログイン・初回設定画面と `auth.js`・`style.css`・`/api/health`・`/api/auth/status|login|setup`
- パスワードは scrypt（N=2^14, r=8, p=1, salt 16 byte）。セッションは Cookie `session`（HttpOnly・SameSite=Lax・30 日）、DB にはトークンの SHA-256 のみ保存。使われたら 1 日ごとに期限を 30 日後へ延長
- ログイン失敗は接続元ごとに 10 分で 5 回までで、超えると 10 分間 429
- `POST /api/auth/password {current, new}`: 変更したブラウザ以外のログインを解除。上部タブ右端にユーザー名とログアウト
- パスワードの再設定: `python -m app.cli reset-password`（Docker: `docker compose exec -u appuser app python -m app.cli reset-password`）。すべてのログインを解除
- docker-compose の既定の公開ポートを `5003:5003`（他の PC からも接続可）に変更

### 10.26 全データのエクスポート
- `GET /api/export`（要ログイン）: `task-idea-hub-export-YYYYMMDD-HHMM.zip` をダウンロード
  - `data.json`（format / version / exported_at と全テーブル。タスクのリンクは配列、タグは各アイディア・メモに付けて出力）
  - `tasks.csv` / `ideas.csv`（BOM 付き UTF-8。Excel 用）
  - `notes/日付_タイトル_ID.md`（アーカイブは `notes/archive/`。中身は画面のエクスポートと同じ）
  - `README.txt`
- users・sessions（パスワードのハッシュ・ログイン状態）は含めない
- 登録画面に「データのエクスポート」欄とダウンロードボタン

### 10.27 土日の表示
- 日表示では、日付見出しの文字を土曜=青・日曜=赤にし、見出しとディシジョン行・全タスク行の土日の列に淡い背景（土=青系、日=赤系）を敷く。週・月表示では色分けしない

### 10.28 フォント
- フォントの候補を `--font-sans` / `--font-mono` にまとめ、Windows（Segoe UI・游ゴシック UI・メイリオ・Consolas）と Linux（Noto Sans CJK JP）のフォントも候補に入れる。以前は Mac のフォントしか指定しておらず、Windows のブラウザでは既定フォントで素朴に見えていた

### 10.29 狭い画面での表示日数
- 列幅の下限と最低列数を 日: 18px・14 日（最大 21 日）／週: 36px・8 週／月: 44px・6 か月 に変更。Windows の表示拡大（150% では 1920px の画面がブラウザから 1280px に見える）で日表示が 7 日まで減っていたため
- 列が 30px 未満のときは日付見出しの文字を 11px にする

### 10.30 ガントの行を 1 行でコンパクトに
- 表のセルの上下余白を 4px（行の高さ約 29px）にし、☀・領域ラベル・バー（高さ 16px、行の中央）も合わせて小さくする
- タスクのリンクはタスク名の下ではなく、同じ行の右側に小さく並べる（最大で欄の幅の半分。入りきらなければ省略）

### 10.31 バーの色
- ガントのバーを優先度の色ではなく領域の色にする（領域が見つからなければ灰色）。優先度は「優先」列の文字色（高=赤・中=橙・低=灰）で表す。完了は薄く、期限切れは赤枠、今日のタスクは黄色の縁取りのまま
- （変更）リンクがあるタスクだけ 2 行にして、2 行目にリンクを小さく細く（10px）並べる。リンクのないタスクは 1 行のまま。バーは行の上下中央に置く

### 10.32 期限の目印
- 未完了で期限まで残り 2 日以内の期限は赤い背景（#ef4444）、期限切れは濃い赤の背景（#991b1b）に白い太字で表示する（以前は赤い文字）

### 10.33 バーのドラッグで期間を変更
- バーの左端をドラッグで開始日、右端をドラッグで期限を 1 日単位で変える（時刻は元のまま）。ドラッグ中はバーの長さと「開始 M/D」「期限 M/D」を表示し、離したら `PATCH /api/tasks/{id}` で保存
- 期限が開始より前になる位置までは動かせない。表示期間の外まで続いている側の端はつかめない
- ドラッグ直後は行のクリック（編集ダイアログ）を開かない
- （追加）バー全体をドラッグすると開始日・期限を同じ日数だけずらす（期間の長さ・時刻はそのまま）。ドラッグ中は「M/D 〜 M/D」を表示。動かさずに離したら（クリック）編集ダイアログを開く

### 10.34 右側（リンク・ブレスト）の開け閉め
- TODO のツールバー右端の「リンク・ブレスト ▸ / ◂ リンク・ブレスト」ボタンで右側をまとめてたたむ・開く。たたむとガントが横幅いっぱいになり、表示日数を計算し直す。状態は localStorage（`todo.sideCollapsed`）に保存

### 10.35 バックアップと復元
- 登録（管理）画面の「バックアップ」: 「今すぐバックアップ」でいつでも作成。一覧（日時・種類・サイズ）から ⬇ ダウンロード・復元・削除
- 保存先は `data/backups/app-YYYYMMDD-HHMMSS[-before-restore][-N].db`（SQLite のバックアップ機能で丸ごと写す）。作成から 30 日を過ぎたものは、一覧の表示・作成のたびに自動で削除
- 復元: まず今の状態を「復元前の自動保存」としてバックアップし、バックアップの写しを今の表の形に合わせて（古い版で作ったものでも可）、データの表（領域・関連項目・タグ・アイディア・メモ・タスク・ディシジョン・ブレスト・リンク）の中身を入れ替える。users・sessions（ログイン）は入れ替えない
- API（要ログイン）: `GET/POST /api/backups`、`POST /api/backups/{name}/restore`、`GET /api/backups/{name}/download`、`DELETE /api/backups/{name}`。名前は決まった形のみ受け付ける

### 10.36 管理タブ
- バックアップ・データのエクスポート・パスワード変更を登録画面から新しい「管理」タブ（`/admin.html`、`static/admin.js`）に移す。登録画面は領域・関連項目・タグのみ
- 上部タブ: TODO / NOTES / アイディア / 登録 / アーカイブ / 管理

- （変更）削除の確認で入力するのは「削除」ではなく、そのバックアップの日付を 8 桁の数字で（例：「20260929」。全角数字も可）

### 10.37 一覧のドラッグと区切り線
- NOTES の一覧は「日付順」のときも ⋮⋮ でドラッグして並べ替えられる。日付順でドラッグしたら並び順を「手動」に切り替えて知らせる
- メモ一覧・アイディア一覧の項目の間に、はっきりした線（#cdd3da、最後の項目の下にも）を引き、上下の余白を広げる
- TODO のガントのタスクの行の間の線を、薄いが見える灰色（#d6dbe1）にする

### 10.38 メモのコピー
- NOTES の編集欄の「📋 コピー」とアーカイブのメモ行の「📋」で、メモの Markdown（エクスポートと同じ中身）をクリップボードにコピーする
- コピーは `static/ui.js` の `copyText`: https / localhost では Clipboard API、http で社内サーバーを開いた場合など使えないときは textarea を選択して `execCommand("copy")` に切り替える（リンクリストのパスのコピーも同じ処理に変更）

### 10.39 蛍光ペンと文字の色（NOTES）
- 蛍光ペン `==文==` → `<mark>`（内側の先頭・末尾が空白なら対象外、コードの中は対象外）
- 文字色 `<span style="color:…">文</span>`。表示時は nh3 で span の style を color だけに絞る
- 編集欄の書式バー: 「🖍 蛍光ペン」と 5 色（赤・青・緑・橙・紫）。編集中のブロックで選んだ文字を囲む。選んでいなければ案内を表示
- どのアプリでも読める Markdown にするため、画面のエクスポート・コピーと全データ ZIP の notes/*.md では、蛍光ペンと文字色の書き方を取り除き中の文章だけ残す（`app/markdown_portable.py` と `static/noteExport.js` の同じ処理。コードの中は変えない）。data.json は書いたとおり残す
- （変更）書式バーは説明文なし。蛍光ペンは文字・絵文字なしの黄色の四角、文字色は色の丸（名前はツールチップ）

### 10.40 完了タスクのアーカイブ

- tasks に `done_at`（完了した日時）を追加。完了にしたときに記録し、未完了に戻すと消す。導入前に完了していたタスクは `updated_at` を完了日時とする
- 完了から 2 日（48 時間）たったタスクは `GET /api/tasks` に含めず、`GET /api/tasks/archived`（完了の新しい順、`q` で検索）で返す
- ARCHIVE タブに「タスク」を追加（1 行表示、クリックでメモ・リンク・期間）。「戻す」で未完了に戻して TODO へ、「削除」で完全に削除
- 完了から 1 年（365 日）たったタスクは、TODO・アーカイブの一覧を読み込んだときに自動で削除する
- `GET /api/tasks/archived.csv` でアーカイブしたタスクを CSV（BOM 付き UTF-8）でダウンロード。全データの tasks.csv と同じ列（完了日時を追加、開始・期限は日付のみ）
